# Engineering

Implementation plans, plus the code-repo registry and codebase maps that ground product answers in real code.

**Read this when:** You need to know how a feature will be built, or which repo implements what.

> The registry entries and the map are a synthetic worked example (fictional product Beacon). Replace them with your real repos via `/connect-code`.

## Contents

### Subfolders

- [plans/](plans/) — Implementation plans by product area; also the text-fallback home for `/create-tickets` output
- [codebases/](codebases/) — SHA-stamped codebase maps ("table of contents" per large product repo), generated by `/connect-code`

### Files

- [code-repos.yaml](code-repos.yaml) — Registry of product code repos: remote, coverage, entry points, deployed ref, access tier — Tier 0 of code grounding (`/code-qa`)
