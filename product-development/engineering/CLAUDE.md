# Engineering

Engineering plans, RFCs, bug investigations, the code-repo registry, and codebase maps.

**Read this when:** You need implementation detail, the history of a production issue, or to know which repo implements what.

> The only contents are the synthetic billing worked example (RFC, plan, and bug investigation for the credit usage dashboard) plus matching synthetic entries in the code-repo registry and maps. The structure is ready — file real artifacts into it as engineering work lands.

## Contents

### Subfolders

- [bug-investigations/](bug-investigations/) — Incident and bug investigation writeups by product area
- [plans/](plans/) — Implementation plans by product area
- [rfcs/](rfcs/) — Architectural proposals and decisions by product area
- [codebases/](codebases/) — SHA-stamped codebase maps ("table of contents" per large product repo), generated by `/connect-code`

### Files

- [code-repos.yaml](code-repos.yaml) — Registry of product code repos: remote, coverage, entry points, deployed ref, access tier — Tier 0 of code grounding (`/code-qa`)
